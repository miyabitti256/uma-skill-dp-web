# トレーナー技能試験スコア最適化 仕様調査メモ

対象: 「ウマ娘 プリティーダービー」トレーナー技能試験（2026-11 時点 / 駿大祭編）
目的: 本ツール（uma-skill-dp-web）に「技能試験スコア最大化」モードを追加するための仕様整理

凡例: **確定** = 複数ソース一致 / **有力** = 単一または二次情報 / **不明** = 未確認

---

## 1. 技能試験とは

- 対象シナリオでウマ娘を1回育成し、その**育成終了時の評価点**をもとにスコアを競う期間限定イベント。**レースは走らない**（課程＝採点ルール）。**確定**
- 課程は 5〜7 種類。**現行(2026-10)は 短距離／マイル／中距離／長距離／ダート／エクストラ／フリー の7課程**。**確定**
- 上位課程の解放条件: 1〜5課程で「可」以上 → エクストラ解放 → エクストラ「可」以上 → フリー解放。**確定**
- 主戦場は**フリー課程**（ランキングスコアもここ）。**確定**

> 課程構成は**イベント回ごとに変わる**（2025年の無人島／メカウマ娘編は 逃げ／先行／差し／追込／エクストラ／フリー の6課程＝脚質軸）。**確定**
> → 実装では課程を固定値にせずデータ化する。

---

## 2. スコア計算式（全体像）

```
スコア = 評価点 × 課程倍率 + スコアボーナス
スコアボーナス = スキル獲得 + 基礎能力 + レース勝利 + シナリオ
```

- **課程倍率**は評価点にのみ乗算。**ボーナスには乗らない**。**確定**（wikiru）
  - 課程倍率: 課題適性 A以上=1.0、以降1段階ごとに −0.1（B=0.9, C=0.8, … G=0.4）。**有力**
  - **エクストラ／フリーは課題適性の指定なし = 常に1.0**。**確定**
- **フリー課程では 課程倍率=1.0、かつスキルボーナスの指定リストが無い（＝全スキーが対象）**。**確定**
- フリー課程の式は `スコア = 評価点 + スコアボーナス` に簡約される。**確定**

> 注意: 「フリーは適性補正なし」という記述は**課程倍率が1.0**という意味であり、**評価点の内部でかかるスキル単位の適性倍率（3章）は普通にかかる**。ここを混同すると計算が合わない。**確定**

---

## 3. 評価点側（既存ツールのロジックをほぼそのまま流用可能）

```
評価点 = ステータス評価点 + 固有スキル評価点 + Σ(獲得スキル評価点)
獲得スキル評価点 = round(基礎評価点 × 距離適性倍率 × 脚質適性倍率)
```

- 固有スキル評価点 = **固有Lv × 170**。**有力**
- 適性倍率: S/A=1.1、B/C=0.9、D/E/F=0.8、G=0.7。**確定**
- **芝・ダート適性は倍率に影響しない（常に1.0）**。効くのは距離適性と脚質適性のみ。**確定**
- 条件が複数: 「または」型（＜先行/差し＞）は**良い方**を採用、「かつ」型（＜先行・中距離＞）は**乗算**。**確定**
- **基礎評価点は同一系統内で累積値**（＝上位スキルの基礎評価点は下位を含んだ合計）。**確定**
  - 例: 中距離直線○=217 / 中距離直線◎=262（◎の純増は45）
  - 例: 軽い足取り(白)=217 → 意気衝天(金)=508
- **進化は置換**。評価点は進化後の値になり、進化にSPは不要。**確定**
- 本リポジトリの `public/data/skill_master.json` の `gradeValue` は**この累積・基礎評価点そのもの**で、公開値と完全一致する（4章の検証参照）。

## 4. スコアボーナス側

### 4.1 スキル獲得ボーナス — **確定**

| 区分 | ポイント | master データ上の判定 |
|---|---|---|
| ノーマル（白・**緑も含む**） | **+400** | `rarity === 1` |
| レア（金） | **+1,200** | `rarity === 2` |
| 進化 | **+1,500** | `rarity === 6` |
| 固有 | **対象外（0）** | `rarity === 3..5`（`needSkillPoint === 0`） |
| マイナス効果（デバフ） | **対象外** | `groupRate <= 0` / `gradeValue < 0` |

- 値は**スキルによらず完全フラット**。SP や基礎評価点に依存しない。**確定**
- **継承固有はノーマル（+400）扱い、継承進化は進化（+1,500）扱い**。**確定**
  - データ上も整合: 継承固有 = `rarity 1`（基礎180/sp200）、継承進化 = `rarity 6`（基礎240/sp0）

#### 系統ルール（最重要）— **確定**
> **1系統につき最上位の1個だけが加算される。** 系統 = 同一 `groupId`（昇格ライン）。

| ケース | ボーナスの挙動 |
|---|---|
| ○ → ◎（白→白） | **増えない**（400 → 400）。◎を取る意味は評価点純増 45×適性倍率のみ |
| 白 → 金（同一系統） | 1,200 のみ（純増 +800） |
| 金 → 進化 | 1,500 のみ（純増 **+300**、1,200は消滅） |
| 継承固有(400) → 継承進化(1,500) | 純増 **+1,100** |

これは本リポジトリの既存 DP（`groupId` 単位で1グループ1選択、上位ティアは下位のコスト/評価点を内包）と**そのまま整合する**。系統ルールの実装は「グループの選ばれた最上位オプションの rarity でボーナスを決める」だけでよい。

### 4.2 対象スコアボーナススキル（課程別）— **確定**

- **フリー課程: 指定リストなし = 全スキーが対象**（固有・デバフのみ除外）。
- 距離課程／エクストラ: 課程ごとに「+400 群（7件）」「+1,200 群（7件）」の**指定リストがあり、リスト外はボーナス0**。
- 落とし穴: **進化スキルは別ID**のため、距離課程で進化先が指定リストに無いと**元の1,200が消えて0になる**。
- 現行(駿大祭編)の共通コア: +400 = 快速／末脚／直線巧者／彼方の呼び声、+1,200 = 神速／全身全霊／ハヤテ一文字／名にし負う夢（残り3枠ずつが課程固有）。
- リストは**イベント回ごとに差し替わる**（枠数 7+7 は共通）。

### 4.3 基礎能力ボーナス — **有力（版差あり）**

| 条件 | 現行(2026) | 旧(2022〜2024) |
|---|---|---|
| 各ステータス 1,000以上 | +3,000 | +1,500 |
| 各ステータス 1,201以上 | +2,000 | +1,000 |
| スピード 2,001以上 | +1,000 | なし |

- 5ステータスに独立適用。**スキル選択とは完全に独立**（＝最適化の変数ではない）。合計に足すだけ。

### 4.4 レース勝利ボーナス — **確定**

- GI +100 / GII +70 / GIII +50 / OP +20（1勝ごと）。URAファイナルズはG1扱い。
- これも**スキル選択と独立**。

### 4.5 シナリオボーナス — **確定（版依存）**

- シナリオ固有（例: L'Arc = SSマッチ40勝+1,500 等）。イベント回ごとに表が必要。現行分は**不明**。

## 5. 計算式の検証（公開値との一致）

`round(基礎評価点 × 適性倍率) + スキルボーナス` で公開されている効率値が再現できる。

| スキル | 基礎 | 適性 | 評価点 | +ボーナス | 合計 | SP | 効率 | 公開値 |
|---|---|---|---|---|---|---|---|---|
| 読解力 | 85 | A(1.1) | 94 | +400 | 494 | 120 | 4.12 | 493/120=4.10 |
| テンポアップ | 217 | A(1.1) | 239 | +400 | 639 | 160 | 3.99 | **3.99** |
| 70緑（右回り○等） | 129 | なし(1.0) | 129 | +400 | 529 | 70 | 7.56 | **529** |
| 継承進化 | 240 | A(1.1) | 264 | +1,500 | 1,764 | 200 | 8.82 | **1,764** |
| 意気衝天（金） | 508 | A(1.1) | 559 | +1,200 | 1,759 | 160 | 10.99 | ― |

→ 本ツールの既存関数 `calculateEffectiveGradeValue()`（`Math.round` 込み）がそのまま使える。

> 注記: **継承進化の 1,764 は「適性1.1倍がかかる」前提の値**。`skill_master.json` の継承進化スキル（例: 91101351）は、以前は `distanceTypes`/`runningStyles` が空で 1,740 と計算されていた（説明文には ＜差し/追込＞ と明記されていたため）。
> **2026-11-20 のマスタデータ更新で当該条件がデータ側に反映され**、現在は **240 × 1.1 + 1,500 = 1,764** が再現される（詳細は設計書 §14）。

### 3.1 説明文にしか書かれていない適性条件

- 一部スキルは、`distanceTypes`/`runningStyles` が空なのに説明文に `＜差し/追込＞` `＜中距離＞` 等の条件を持つ。**確定**（実データで74件、うち購入・進化対象は38件）
- ただし「説明文に書いてあっても実際には条件が適用されない」ケースもある（例: `我が意、即ち天の理なり` の「2000m以上」には ＜中距離・長距離＞ 条件が付かない）。**確定**（ml'p 氏の検証）
- → マスタデータ側で解消済み（2026-11-20 の更新で `distanceTypes`/`runningStyles` に反映）。**説明文からの自動変換は行わない**方針は変わらない（「書いてあっても条件にならない」ケースがあるため）。

## 7. 最適化問題としての定式化

### 7.1 目的関数

```
maximize  a · Σ_g v_g(d_g)  +  Σ_g b_g(d_g)
```
- `a` = 課程倍率（フリー = 1.0）
- `g` = 系統（`groupId`）、`d_g` = その系統で選ぶスキル（未取得なら ∅）
- `v_g(d)` = 系統 g の評価点（累積値・適性倍率適用済み）
- `b_g(d)` = 系統 g のスキルボーナス（選んだ最上位の rarity で 0/400/1200/1500）

**(a·v + b) は系統ごとに独立に加算されるので、既存 DP の目的関数を差し替えるだけで厳密最適が求まる。** 制約（SP予算、系統内1選択、進化スロット 12状態、ロック/除外）は既存実装をそのまま流用できる。

### 7.2 既存実装との差分

| 項目 | 既存（評価点最大化） | 技能試験モード |
|---|---|---|
| オプション価値 | `Δ評価点` | `a·Δ評価点 + Δボーナス` |
| コスパ表示 | pt / SP | スコア / SP |
| 適性倍率 | 育成ウマ娘の適性 | 同左（**フリーでも同じ**） |
| 進化の価値 | `evoEff − baseEff` | `+ 300`（金→進化）/ `+ 1,100`（継承固有→継承進化） |
| 目標表示 | 評価ランク | スコア・優ライン到達判定 |

### 7.3 挙動が変わるポイント（＝この機能の価値）

1. **安いスキルが激変**。固定 +400 が乗るため、評価点が低くても SP が安いスキルが最適解に入る（例: 読解力 4.12 > テンポアップ 3.99。査定では逆転していた）。
2. **◎は実質無価値**。同じ +400 で評価点純増は 45×適性倍率のみ。「◎は絶対取るな」が最適解として自然に出る。
3. **進化の優先度が上がる**。金の進化は +300、継承進化は +1,100 の追加価値。
4. **スキル数が正義**になり、SP 予算が常に拘束する（評価点最大化より「たくさん取る」寄り）。

## 8. 実装方針案

### 8.1 データ

- `public/data/skill_master.json` は**変更不要**（rarity / groupId / groupRate / gradeValue / needSkillPoint で全部判定できる）。
- 新規 `public/data/skill_test_courses.json`（版管理用）:
  ```jsonc
  {
    "editions": [{
      "id": "2026-10", "name": "駿大祭編", "scenarioId": 15,
      "skillBonus": { "normal": 400, "rare": 1200, "evolved": 1500 },
      "statBonus": [{ "threshold": 1000, "points": 3000 }, ...],
      "courses": [{
        "id": "free", "name": "フリー課程",
        "aptitudeAxis": "none",            // distance:short | surface:dirt | style:nige | none
        "courseMultiplier": 1.0,           // 軸なしは常に1.0
        "bonusSkills": null,               // null = 全スキー対象（フリー）
        "thresholds": { "ka": null, "ryo": null, "yu": null }
      }]
    }]
  }
  ```

### 8.2 ソルバ

- `SolverOptions` に `mode: 'grade' | 'skillTest'`、`courseMultiplier`、`skillBonusTable`、`bonusSkillFilter?` を追加。
- `DpOption` に `scoreBonus` を持たせ、`dpCost`/`effectiveGrade` と同様に**ボーナス差分**を計算。
- バックトラック後の集計で `評価点` と `スキルボーナス` を分けて返す（内訳表示のため）。
- フリー課程は `bonusSkillFilter = null`（全対象）、距離課程は指定リストでフィルタ。

### 8.3 UI

- `ConditionPanel` に「技能試験モード」トグル＋課程セレクタ＋ステータス5値入力（基礎能力ボーナス算出用）。
- `OptimizationPanel` をモード切替: 見出しを「到達想定スコア」に、内訳（評価点 / スキルボーナス / 基礎能力 / レース）と**優ライン到達可否**を表示。
- 推奨行の「効果 +pt」を「スコア +pt」に、内訳ツールチップ（評価点 +239 / ボーナス +400）。

### 8.4 テスト

- `scripts/test-standalone.mjs` に追加:
  - 70緑/継承進化/意気衝天のスコア・効率が公開値と一致
  - ○→◎ で ボーナスが増えないこと
  - 金→進化 で +300、継承固有→継承進化 で +1,100
  - フリー課程: 固有・デバフが加点されないこと
  - 技能試験モードの最適解が評価点最大化の最適解と異なること（回帰）
